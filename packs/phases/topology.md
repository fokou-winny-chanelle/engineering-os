# Architecture topology

The repo's shape is in the AGENTS.md topology block, from `eos topology`. Use the decisions pack to choose a shape. This pack covers working inside one.

## Entry
- The shape is known: single app, modular monolith, microservices, monorepo, or a multi-repo workspace.
- The change crosses a module, service or repo boundary, or adds one.

## Standards
1. **Default to a modular monolith:** one deployable, with modules that own their data and expose a small public API. Split out a service only for a reason written in an ADR: independent scaling, a separate team, or a compliance or fault-isolation boundary.
2. **Boundaries are code, not a wish.** Check them in CI with a fitness function, and write its error message as the fix ("import billing.api instead of billing.internal"):
   - import-linter (Python);
   - dependency-cruiser (JS/TS);
   - ArchUnit (JVM);
   - Packwerk (Ruby);
   - Nx module boundaries.

   `eos scaffold boundaries` writes the config. New violations fail; old ones go in a baseline (ratchet).
3. **Module rules:**
   - one owner per module (`docs/architecture/modules.md`, CODEOWNERS);
   - no cycles;
   - no reaching into another module's tables;
   - talk through the public API, or through domain events for side effects.

   `eos new module <name>`.
4. **Service rules:**
   - one service, one owner, its own data store;
   - contracts are the only coupling: OpenAPI for HTTP, protobuf for gRPC, AsyncAPI for events;
   - every remote call has a timeout, retries with backoff, idempotency and a fallback.
5. **Contracts change additively:** expand → migrate consumers → contract. Breaking changes need a new version, and the old one stays until no consumer uses it. Guard contracts in CI (oasdiff, `buf breaking`) and with consumer-driven contract tests (Pact) where teams differ.
6. **Service template:** `eos new service <name>` creates:
   - README (purpose, owner, SLO);
   - `catalog-info.yaml` (Backstage format);
   - a contract stub;
   - a nested AGENTS.md;
   - a catalog row in `docs/architecture/services.md`.

   Copy the code skeleton from the best existing service (or the framework generator).
7. **Shared code policy:**
   - share technical libraries (logging, auth client, HTTP client), versioned, each with an owner;
   - never share domain models or databases across services;
   - prefer a little duplication over coupling.
8. **Monorepo:** each app or package has its own checks (AGENTS.md table) and CI path filters. Apps never import apps. Run affected checks only (Nx/Turborepo/pnpm `--filter`, uv workspace members). Lockfiles live at the workspace root.
9. **Multi-repo workspace** (`eos workspace …`):
   - the parent `AGENTS.md` maps the repos, their roles, contracts and owners;
   - each repo keeps its own rules;
   - a cross-repo change gets a plan (`eos workspace change`), the same branch name in every repo, linked PRs, and merges in order: provider first, then consumers, then cleanup.
10. **Local orchestration:** `compose.yaml` runs every service plus its dependencies, with health checks and profiles for optional parts; `docker compose up --wait` starts it all.


## Deliverables
- An updated catalog (services or modules), a boundary config and contract files.
- An ADR for any new service or split.

## Automated checks
- The boundary check (import-linter / dependency-cruiser) in CI and in the ratchet.
- A contract breaking-change check per provider (`eos scaffold api-contract`).
- CI per app or service with path filters (generated by `eos init`).

## Deep references

## Exit checklist (Definition of Done)
- [ ] The boundary check is green, and nothing new is in the baseline.
- [ ] Contracts change additively, or a version bump with a migration plan for consumers exists.
- [ ] The catalog and owners are updated, and the linked PRs are listed for cross-repo work.

## Handoff → api-design, testing-qa, infra-devops

## Stop & escalate
Stop and escalate when:
- a change needs a breaking contract change;
- two services must share a DB;
- a module needs another module's internals.

Present the options (ADR); don't decide alone.
