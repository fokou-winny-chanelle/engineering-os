# Flaky tests: policy

Generated by `eos scaffold quarantine`; yours to edit. Background: `.eos/packs/ref/testing/flaky-speed.md`.

A flaky test passes and fails on the same code. Treat it as a bug in the test or the product, never as noise.

1. **Detect.** CI retries a failed test once (`retries: 1` in Playwright on CI, `--reruns 1` with
   pytest-rerunfailures if you add it) only to collect a trace and label it flaky. A pass on retry is still
   reported. Find suspects locally with `pytest -p randomly` / `--count`, `playwright test --repeat-each 20`.
2. **Quarantine within a day.** `eos quarantine add <test id> --reason "<symptom>" --owner @you --issue <url>`
   writes `tests/quarantine.json`. pytest marks those tests `xfail(strict=False)` (they run, cannot fail the
   build); Playwright skips them through `grepInvert` in `playwright.config.ts`. A human reviews the change
   (`eos test-integrity` flags it).
3. **Expiry.** Entries expire after at most 14 days (`testing.quarantine_max_days` in `.eos/config.json`).
   `eos check` (CI) fails once an entry has expired: fix the test, delete it with a reason in the PR, or
   re-add it with a new ticket and a human's approval.
4. **Fix the cause.** Usual causes: shared state or test order, real time and timezones, random data without
   a seed, sleeps instead of waiting for a condition, real network, leaked resources, and races in async code.
5. **Never:** blanket retries to get green, `skip` without an entry here, or raising timeouts until it passes.
