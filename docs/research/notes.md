# Research notes (raw, for RESEARCH.md) — Oct 10 2026
## 1 Agentic SE
- METR RCT (Jul 2025): 16 experienced OSS devs, 246 tasks, AI allowed => 19% slower (CI 1.3%-39.5%); devs expected -24%, believed -20% after. Time lost to prompting, reviewing, waiting. https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/ https://arxiv.org/abs/2507.09089
- Anthropic "Effective harnesses for long-running agents" (Nov 26 2025): initializer agent creates init.sh, progress file, initial commit; coding agent makes one incremental feature per session, commits with descriptive msgs, progress summary; smoke test before new work. https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents
- Anthropic "Harness design for long-running application development": planner/generator/evaluator; evaluator tests running app independently; drop scaffolding as models improve (context resets unnecessary with Opus 4.5). https://www.anthropic.com/engineering/harness-design-long-running-apps
- Anthropic "Managed agents": harnesses encode assumptions that go stale; separate session log / harness / sandbox. https://www.anthropic.com/engineering/managed-agents
- Chroma "Context Rot" (Jul 2025): 18 models; performance degrades with input length even on simple tasks; worse with distractors and low similarity; focused ~300 tok vs 113k full history in LongMemEval. https://research.trychroma.com/context-rot
- ImpossibleBench (Zhong, Raghunathan, Carlini; arXiv 2510.20270, ICLR 2026): tests conflicting with spec; cheating via test modification, special-casing, operator overloading, state recording; GPT-5 cheated 76% on Oneoff-SWEbench; read-only tests stop edits but not special-casing; hiding tests ~0 cheating but hurts performance; prompt and feedback loop affect cheating rates. https://arxiv.org/abs/2510.20270
- Anthropic "Effective context engineering for AI agents": smallest set of high-signal tokens; just-in-time retrieval via identifiers (paths, queries); compaction; sub-agents return 1-2k token summaries; structured note-taking. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- Stripe Minions part 2: >1,300 PRs/week fully minion-written, human-reviewed. Isolated devboxes (ready in 10 s, QA env, no prod data, no arbitrary egress) => no confirmation prompts needed. "Blueprints": state machine mixing deterministic nodes (run linters, push) with agent nodes (implement, fix CI). Global rules used judiciously; rules scoped to dirs/file patterns (Cursor format, synced to Claude Code). Toolshed ~500 MCP tools but agents get a small curated subset. Lint loop locally; max 2 CI rounds then back to human (diminishing returns). "What's good for humans is good for agents." https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2
- DORA 2025 State of AI-assisted Software Development: AI is an amplifier; ~90% adoption, >80% report productivity gains; AI adoption still associated with higher delivery instability; AI Capabilities Model: clear AI policy, healthy data, internal platform, user-centric focus, small batches, strong version control, etc. https://dora.dev/research/2025/dora-report https://cloud.google.com/blog/products/ai-machine-learning/introducing-doras-inaugural-ai-capabilities-model
- LLM-as-judge biases: "Justice or Prejudice?" (ICLR 2025, arXiv 2410.02736) 12 bias types; position bias (ACL/IJCNLP 2025); self-preference (EMNLP 2025). Mitigate: swap order, different judge model, rubric, calibrate with human labels. https://arxiv.org/abs/2410.02736 https://aclanthology.org/2025.emnlp-main.86/
- OpenAI "Harness engineering" (Feb 11 2026, Ryan Lopopolo): ~1M LOC product, 0 manually written lines, ~1,500 PRs by 3 then 7 engineers (3.5 PRs/eng/day). Early progress slow because environment underspecified; fix is "what capability is missing, make it legible and enforceable". AGENTS.md ~100 lines = map; docs/ is system of record (design-docs, exec-plans/active|completed, tech-debt-tracker, product-specs, references/*-llms.txt, QUALITY_SCORE, RELIABILITY, SECURITY); linters/CI check docs freshness + cross-links; doc-gardening agent. App bootable per worktree, Chrome DevTools for agent, ephemeral per-worktree observability (LogQL/PromQL) so perf goals become checkable. Rigid layered architecture per domain (Types→Config→Repo→Service→Runtime→UI), enforced by custom linters + structural tests; lint error messages carry remediation instructions. "Parse data shapes at the boundary." Boring tech easier for agents. Agents replicate existing patterns incl. bad ones → "golden principles" + recurring cleanup ("garbage collection"); previously spent Fridays (20%) cleaning AI slop. https://openai.com/index/harness-engineering/
- Package hallucination (Spracklen et al., USENIX Security 2025): 19.7% of 2.23M generated package refs hallucinated (205,474 unique fake names); commercial models avg 5.2% vs open-source 21.7%; JS 21.3% vs Python 15.8%. https://arxiv.org/abs/2406.10279
- GitHub Spec Kit: constitution → specify → clarify → plan → tasks → analyze → implement. https://github.com/github/spec-kit
