# Operations / SRE & observability area: source survey (verified 10 October 2026)

Stage 6 of the knowledge library (docs/LIBRARY.md checklist, step 1). Every source below was opened on 10 October 2026 and the facts the refs rely on were checked against its text (pages were fetched and grepped, not recalled). Tool versions and checksums were read from PyPI, npm and GitHub releases the same day. Verdicts follow the import policy in `v0.7-external-sources.md`: **Import** (vendor pinned), **Adapt** (our own text, cited), **Link** (cite only).

**Imports: none. Adaptations: none.** The Google SRE books (*Site Reliability Engineering*, *The Site Reliability Workbook*) are **CC BY-NC-ND 4.0** (footer of every sre.google chapter), so they are linked only; no text, tables or figures were adapted. OpenTelemetry docs (CC BY 4.0) and the FinOps Framework (CC BY 4.0) could be adapted with attribution, but we wrote our own text and cite them. The PagerDuty Incident Response and Postmortem docs are Apache-2.0; the incident template in `eos scaffold ops` is our own short text that follows their severity and role structure and credits them. Nothing is vendored, so the OWASP sign-off pending since stage 2 is unaffected and nothing new needs `eos vendor review`.

## 2. Enforcement decisions

| Need | Decision | Why |
|---|---|---|
| SLO file | `ops/slo.json` schema checked by `eos ops check` and `eos check` (core CI): service, unique id, journey, owner, objective 50–<100 (warn above 99.99), window 7–90 days, existing runbook, SLI description, `{{window}}` PromQL unless `"alerting": false`. Edits count as a gate change for `eos test-integrity`. | SLOs as code, reviewed like code; milliseconds in-process. |
| Burn-rate alerts | `eos ops alerts` generates Prometheus recording + alerting rules with the Workbook's three burn rates scaled to the window (14.4/6/1 for 30 days; 13.44/5.6/0.93 for 28); `--check` and `eos check` fail when the file is stale. Scaffold ships `promtool test rules` unit tests (fire at 10% errors, silent at 0.3%); ops workflow runs `promtool check rules` + `test rules` from the checksummed Prometheus tarball. | Hand-written burn-rate PromQL is error-prone; tests prove the alert fires. |
| Runbook per alert | Every `- alert:` block in `ops/alerts`, `monitoring/alerts`, `prometheus/rules` needs `labels.severity` and `annotations.runbook_url`; a repo-local runbook must exist (warn without a Mitigation section). `eos ops runbook NAME` writes a template. | Pages must be actionable. |
| Secrets/PII in logs | `.semgrep/eos-ops.yml` (Python + JS/TS): secrets in log calls (ERROR), personal data and whole request bodies (WARNING); ruleid/ok fixtures in `tests/semgrep/`. Telemetry templates also redact secret-named fields. | Logs are copied widely; catch the obvious cases in review. |
| Health/readiness | docker-python scaffold now ships `tests/test_health.py` (liveness ignores dependencies; readiness 503 on failure or hang, no error text leaked); `health.py` gained a per-check timeout. | Probes that hang or leak are common bugs. |
| Dockerfile lint | `.hadolint.yaml` (fail on warning+) and `container.yml` (hadolint from checksummed release binary + `docker build` without push). `eos verify` runs hadolint on changed Dockerfiles in risky lanes when installed. | No new third-party action; fast path untouched. |
| IaC scan | `eos scaffold iac`: `tofu fmt -check`, `init -backend=false`, `validate` per module (checksummed OpenTofu zip), `uvx checkov==3.3.26` with `.checkov.yaml`; plan-only, never apply; `.gitignore` for state and secret tfvars. `eos verify --full` runs checkov on changed IaC folders when installed. | trivy-action was compromised in March 2026; uvx + pin avoids a new action. |
| Feature flags | `ops/flags.json` registry (owner, type, created, expiry ≤ 90 days for release/experiment, rollout 0–100) checked by `eos ops check`; code scan fails on flags read in code but not registered. OpenFeature providers for Python and Node with env overrides, stable percentage rollout (same hash in both languages) and `feature_flag.evaluation` span events. | Fowler's "time bomb" idea enforced in CI; OpenFeature keeps vendors swappable. |
| OpenTelemetry | `otel-python` (FastAPI/Flask, OTLP/HTTP, JSON logs with trace_id, health probes excluded, test) and `otel-node` (Next.js `instrumentation.ts`, Node SDK, JSON logger). No export unless an endpoint is set. | Vendor-neutral; config by standard env vars. |
| Lanes | trivial/spike: nothing new. standard: in-process ops config check when ops files exist. risky/`--full`: hadolint on changed Dockerfiles; `--full`: checkov on changed IaC. Everything else in CI workflows triggered by path. | Fast path stays fast. |
| New actions | none. All new workflows reuse already-pinned `actions/checkout` and `astral-sh/setup-uv`; tools come from checksummed downloads or pinned `uvx`. | SHA-pin rule satisfied without adding supply-chain surface. |

## 3. Human review needed

1. **Objectives and thresholds are policy.** 99.5%/99.0% example SLOs, 90-day flag limit, page vs ticket split and the incident response times are defaults, not measurements. Agree them with whoever carries the pager.
2. **Production changes stay human.** The IaC workflow never applies; `apply`, DNS, database restores and failovers need a named human, a GitHub environment with required reviewers, and a rollback plan.
3. **Incident data.** Postmortems and timelines must not copy personal data or secrets; data-breach notification duties (GDPR 72 h; Cameroon Law 2024/017, see `security/privacy`) are legal calls.
4. **Data residency.** Where data may be stored (South African regions vs EU vs local hosting) depends on the law and contracts in each market; the refs give facts, not legal advice.
5. **Checkov/hadolint findings** are reviewed like security findings; skips need a reason in the code.
6. The OWASP vendored sources from stage 2 remain pending human sign-off (`eos vendor review` not run).
