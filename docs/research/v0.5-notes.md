# Research notes for v0.5.0 (any project state, self-guiding, topologies)

Checked 2026-10-10. Each line says what was found and what eos does with it. The full reference texts that packs read on demand are `packs/ref/migration-playbook.md` and `packs/ref/topologies.md`.

## 1. Bringing existing code under gates: the ratchet
- **Prior art.** Several mature tools hold new code to a higher standard than old code by recording today's violations once:
  - ESLint's native bulk suppressions (`--suppress-all` writes `eslint-suppressions.json`) ([ESLint](https://eslint.org/docs/latest/use/suppressions));
  - PHPStan's `--generate-baseline` ([PHPStan](https://phpstan.org/user-guide/baseline));
  - Betterer, which fails when a metric gets worse and updates its results when it improves ([Betterer](https://phenomnomnominal.github.io/betterer/docs/introduction));
  - dependency-cruiser's `depcruise-baseline` plus `--ignore-known` ([dependency-cruiser CLI](https://github.com/sverweij/dependency-cruiser/blob/main/doc/cli.md)).
- **What eos does.** It uses one tool-agnostic ratchet over each project's own linters, so the idea also works where the linter has no baseline feature (ruff, mypy, tsc). Fingerprints drop line numbers, so moved code isn't "new". A crashed command is never recorded as a clean baseline. Counts can only go down (`update` / `--tighten`). Where a native baseline exists (ESLint, PHPStan, dependency-cruiser), the team can use that instead and point `eos ratchet add` at the command.

## 2. Rewrites (refonte) and refactors
- Big-bang rewrites are a well-documented failure mode ([Spolsky](https://www.joelonsoftware.com/2000/04/06/things-you-should-never-do-part-i/)).
- The incremental alternative is the strangler fig: a seam, then thin slices, then retiring the old path ([Fowler](https://martinfowler.com/bliki/StranglerFigApplication.html), [Azure Architecture Center](https://learn.microsoft.com/en-us/azure/architecture/patterns/strangler-fig), [Shopify](https://shopify.engineering/refactoring-legacy-code-strangler-fig-pattern)). Supporting techniques:
  - branch by abstraction ([Fowler](https://martinfowler.com/bliki/BranchByAbstraction.html));
  - parallel change, also called expand/contract ([Fowler](https://martinfowler.com/bliki/ParallelChange.html));
  - feature toggles ([Fowler](https://martinfowler.com/articles/feature-toggles.html), [OpenFeature](https://openfeature.dev/)).
- **Safety net first**: characterization / golden-master tests ([Wikipedia](https://en.wikipedia.org/wiki/Characterization_test), [ApprovalTests](https://approvaltests.com/)).
- **Parity by dual run**: GitHub's Scientist library ([Scientist](https://github.com/github/scientist)) and Stripe's four-phase online data migration ([Stripe](https://stripe.com/blog/online-migrations)). Change data capture for data moves ([Debezium](https://debezium.io/)).
- **What eos does.** The `migration` pack, `eos new migration` (plan with seam and slice table, parity report, data-migration plan, cutover and rollback runbooks, `tests/characterization/`), and rewrite-mode phases whose exit criteria read those files: seam filled, safety-net boxes ticked, every slice live, cutover preconditions ticked, old paths removed.

## 3. Architecture topologies
- **Fitness functions.** Boundaries hold only if a check enforces them ([ThoughtWorks Radar](https://www.thoughtworks.com/radar/techniques/architectural-fitness-function)). Tools by ecosystem:
  - import-linter `independence` contracts with wildcards and `broken_contract_guidance` ([import-linter](https://import-linter.readthedocs.io/en/stable/contract_types/)); Tach ([Tach](https://github.com/gauge-sh/tach));
  - dependency-cruiser rules with group matching ([rules reference](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md)). Version 18 declares Node ^22, ^24 or ≥26 in its `engines` field; on Node 20, v16 works (tested);
  - Nx module boundaries ([Nx](https://nx.dev/docs/features/enforce-module-boundaries)), ArchUnit ([ArchUnit](https://www.archunit.org/)), Spring Modulith ([Spring](https://spring.io/projects/spring-modulith)), Packwerk ([Packwerk](https://github.com/Shopify/packwerk)).
- **Microservices.**
  - Database per service ([microservices.io](https://microservices.io/patterns/data/database-per-service.html)).
  - Contracts checked for breaking changes ([oasdiff](https://github.com/oasdiff/oasdiff), [buf](https://buf.build/docs/breaking/), [AsyncAPI](https://www.asyncapi.com/), [Pact](https://docs.pact.io/)).
  - A catalog descriptor ([Backstage](https://backstage.io/docs/features/software-catalog/descriptor-format)).
  - Local orchestration with Compose profiles ([Docker](https://docs.docker.com/compose/how-tos/profiles/)).
- **Monorepos**: pnpm and uv workspaces, Turborepo ([pnpm](https://pnpm.io/workspaces), [uv](https://docs.astral.sh/uv/concepts/projects/workspaces/), [Turborepo](https://turborepo.com/docs)).
- **What eos does.** It detects the shape, adds one short AGENTS.md block (modules, services or apps), scaffolds boundary configs, seeds service and module catalogs, and wires CI and hooks per app dir.

## 4. Multi-repo workspaces: how each agent reads instructions
- **Cursor** scopes nested `AGENTS.md` to their folder ([Cursor rules](https://cursor.com/docs/rules)). A forum report says that in multi-root workspaces a repo's root `AGENTS.md` can apply across the workspace ([forum](https://forum.cursor.com/t/agents-md-leaks-into-other-repositories-in-multi-repo-workspace/155477)). **So eos recommends opening the parent folder.**
- **Claude Code** loads `CLAUDE.md` files in subdirectories on demand when it reads files there ([memory](https://code.claude.com/docs/en/memory), [large codebases](https://code.claude.com/docs/en/large-codebases)). **So a workspace `CLAUDE.md` imports the workspace `AGENTS.md`, and each repo keeps its own.**
- **Cline**: in multi-root workspaces, rules load only from the primary (first) folder ([multi-root](https://docs.cline.bot/features/multiroot-workspace)). Rules can be made conditional with `paths:` frontmatter ([Cline rules](https://docs.cline.bot/customization/cline-rules)). **So eos puts the workspace folder first in the `.code-workspace` file and writes path-scoped pointers plus re-prefixed repo rules into the workspace `.clinerules/`.**
- **Codex** reads `AGENTS.md` from the project root down to the working directory ([Codex](https://developers.openai.com/codex/guides/agents-md)). **So start it inside the repo; the repo's workspace block points to `../AGENTS.md`.**
- **Linking.** VS Code multi-root files use relative paths ([VS Code](https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces)). GitHub links PRs to issues but has no native cross-repo PR dependency ([GitHub](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue)). **So a plan file in the workspace (`docs/changes/`) is the source of truth for merge order.**

## 5. BMAD (pinned v6.12.1) for existing code
- `bmad-project-context` sets up or audits the repository's agent instructions. Older ids such as `bmad-generate-project-context` forward to it ([project context](https://docs.bmad-method.org/explanation/project-context/), [skills and agents](https://docs.bmad-method.org/reference/skills-and-agents/)).
- The website documents unreleased `main`, where the guide hub is called `bmad`. The pinned v6.12.1 uses `bmad-help` (see docs/BLUEPRINT.md section 8).
- **What eos does.** `eos adopt` first (no overwrites, ratchet, plan), then `bmad-project-context`. `eos next` names BMAD skills for planning steps only when `_bmad/` exists.

## 6. Guiding without nagging
- **Design choices** (judgement, not a cited study):
  - one deterministic source of "what next" (a state machine with file-based exit criteria), so agents don't improvise phase logic;
  - blockers first;
  - one suggestion at the end of a verified task, never mid-task, never repeated after being ignored;
  - explanations live in `eos explain`, outside the agent context.
- **Cost**: about 33 always-on tokens for the core line, about 27 for the navigator skill description, and 30 for teaching mode (optional).
