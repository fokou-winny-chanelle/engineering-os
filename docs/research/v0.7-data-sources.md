# Data and databases area: source survey (verified 10 October 2026)

Stage 3 of the knowledge library (docs/LIBRARY.md checklist, step 1). Every source below was opened on 10 October 2026 and the facts the refs rely on were checked against its text (copies were fetched and grepped, not recalled). Verdicts follow the import policy in `v0.7-external-sources.md`: **Import** (vendor pinned), **Adapt** (our own text, cited), **Link** (cite only).

**Imports: none.** The PostgreSQL documentation is under the permissive PostgreSQL Licence, so importing would be allowed, but the refs only need short facts in our own words, and a pinned copy of the manual would go stale with every minor release. Nothing needs human licence sign-off for this stage.

## 2. Enforcement decisions
- **Squawk tuned config** (`.squawk.toml`, scaffold `db-safety`): `pg_version = "18.0"`, `assume_in_transaction = true`. Tested: with the flag, `prefer-robust-stmts` noise disappears and `ban-concurrent-index-creation-in-transaction` fires (correct for runners that wrap each file). squawk does not flag float or `money` columns, hence the extra rules below.
- **Alembic lint via generated SQL**: feasible and tested. `alembic upgrade <down>:<rev> --sql` emits explicit `BEGIN`/`COMMIT` (and a `COMMIT` before an `autocommit_block`), so the script passes `--no-assume-in-transaction`, and excludes the timeout rules (set them in `env.py` `connect_args`, as squawk's Alembic page shows) and `prefer-robust-stmts`.
- **Missing FK index + money-as-float + naive timestamps**: `scripts/db/schema_lint.sql`, run against a freshly migrated database in CI. Tested on PostgreSQL 17 with single-column and composite FKs.
- **Money-as-float in code**: semgrep rules (SQLAlchemy/Django columns, `float()` on money names and `Decimal(<float literal>)`, `parseFloat` on money names, Drizzle `real`/`doublePrecision`) with `--test` fixtures; Prisma `Float` and SQL DDL via generic regex rules, tested by our own fixture checker because `semgrep --test` does not read annotations in `.prisma`/`.sql` files.
