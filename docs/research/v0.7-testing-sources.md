# Testing & QA area: source survey (verified 10 October 2026)

Stage 5 of the knowledge library (docs/LIBRARY.md checklist, step 1). Every source below was opened on 10 October 2026 and the facts the refs rely on were checked against its text (copies were fetched and grepped, not recalled). Tool versions were read from the package registries (PyPI, npm, GitHub releases) the same day. Verdicts follow the import policy in `v0.7-external-sources.md`: **Import** (vendor pinned), **Adapt** (our own text, cited), **Link** (cite only).

**Imports: none. Adaptations under CC BY: none.** No source in this area is published under a licence that allows adaptation of the prose (CC BY or similar) except tool documentation inside Apache-2.0/MIT repositories, and we do not copy that either. The refs are written in our own words and cite every fact. *Software Engineering at Google* is CC BY-NC-ND 4.0 (abseil.io footer), so it is linked only, never adapted. Nothing is vendored, so the OWASP sign-off pending from stage 2 is unaffected and nothing new needs `eos vendor review`.

### Flaky tests, coverage, mutation

| 9 | [Google Testing Blog: Flaky Tests at Google (2016)](https://testing.googleblog.com/2016/05/flaky-tests-at-google-and-how-we.html) | Link | flaky = passes and fails with the same code; about 1.5% of all test runs flaky; almost 16% of tests have some flakiness; about 84% of observed pass→fail transitions involved a flaky test; 1,000-test project at 1.5% → about 15 failures per run |

## 2. Enforcement decisions

| Need | Decision | Why |
|---|---|---|
| Diff coverage | Native `eos diff-coverage` (stdlib: Cobertura XML + LCOV, `git diff -U0` against the merge-base). Default 80% of changed coverable lines; 90% on money/auth/security paths (risk words and `lanes.risky` globs), per Google's per-commit lower threshold. Config `testing.*` in `.eos/config.json`, CI variable `DIFF_COVERAGE_MIN`. Wired into the Python, TypeScript and Flutter stack CI on PRs, and into `eos verify` for risky lanes when a coverage report newer than the edits exists. | Runs in projects without extra installs (eos is already vendored); stricter where bugs cost money; diff-cover stays documented as an alternative. |
| Flaky tests | `tests/quarantine.json` with id, reason, owner, issue, added, expires; `eos quarantine add/list/check`; max 14 days (Fowler suggests limits such as a week; we allow two). `eos check` (core CI) fails on expired or incomplete entries; `eos verify` checks it in standard and heavier lanes; edits to the file count as a gate change for `eos test-integrity`. The pytest conftest template marks active entries `xfail(strict=False)`; the Playwright config skips them via `grepInvert`. Expired entries stop being honoured, so the test fails again. | Quarantine with an owner and an end date, never a silent skip; costs milliseconds. |
| Retries | Playwright: `retries: 1` on CI with `trace: 'on-first-retry'` (already in the scaffold); policy says a pass on retry is still flaky. No blanket reruns for pytest. | Retries are for diagnosis, not for turning red into green. |
| Load testing | `eos scaffold load-k6`: smoke + average-load (ramping-arrival-rate) scripts with thresholds on error rate, p95/p99 per endpoint, dropped iterations and checks; `load.yml` runs on manual dispatch and weekly smoke against `LOAD_BASE_URL`, never per PR. `grafana/setup-k6-action` pinned by SHA (ACTION_PINS + versions.toml). | Thresholds make k6 exit non-zero; scheduled runs keep the fast path fast. |
| Property-based tests | `property-python` (Hypothesis) and `property-node` (fast-check + Vitest) templates: invariants, round trip, oracle; nightly profile registered in the tests-python conftest. | Copyable patterns that pass as generated (run in the tool-contract tests). |
| Mutation testing | `eos mutation-plan` picks changed source files on risky paths (all changed sources with `lane:risky`; all risky files on schedule) and maps them to mutmut module patterns or Stryker `--mutate` lists; `eos mutation-score` judges mutmut's cicd stats or Stryker's JSON (default minimum 60 = Stryker's default "low"). `eos scaffold mutation` adds the CI workflow and a Stryker config. Never in `eos verify`. | Mutation testing pays on money/auth code and is too slow for every change. |
| Lanes | trivial: unchanged. standard: + quarantine expiry (in-process). risky / one-way-door / `--full`: + changed-line coverage from a fresh report and a pointer to CI mutation testing. | No new subprocesses in any lane; heavy tools stay in CI. |

## 3. Human review needed

1. **Thresholds are policy.** 80% / 90% diff coverage, 14-day quarantine and 60% mutation score are defaults from the cited sources, not measurements of this user's projects. A human should confirm or tune them per project (`.eos/config.json` → `testing`).
2. **Mutation and load workflows run code against your app.** `load.yml` targets a URL you set; it must be staging or an agreed window. The mutation workflow runs your test suite many times on GitHub-hosted runners (minutes cost on private repos; no prices quoted here).
3. **Quarantine entries** are reviewed like any test change; `eos test-integrity` flags the file.
4. **k6 is AGPL-3.0.** It is used as a CLI in CI; whether that matters for a given company is a legal question for the owner, not answered here.
5. No CC BY content was adapted in this stage; the OWASP vendored sources from stage 2 remain pending human sign-off (`eos vendor review` not run).
