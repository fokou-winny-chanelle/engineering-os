# LLM application area: source survey (verified 10–11 October 2026)

Stage 10 of the knowledge library (docs/LIBRARY.md checklist, step 1). The sources were opened on 10–11 October 2026 (box clock, WAT). Each fact the refs rely on was checked against the fetched page text, not recalled from memory. The refs carry `verified: 2026-10-10` because `eos` compares dates in UTC. On 11 October 2026 every one of the 78 unique links in `packs/ref/llm/*.md` returned HTTP 200. Meta's WhatsApp pages answer 400 to a browser user agent and 200 to plain curl. The GitHub repo page timed out once with a 504 and gave 200 on retry. Versions come from the official registries (PyPI, npm) on the same days: `openai` (Python) 3.28.0, `@opentelemetry/api` 1.9.1, `opentelemetry-sdk` 1.45.1 (used to test the scaffold), promptfoo 0.124.1, `@google/adk` 2.2.1. The same check covered the framework packages named in `llm/frameworks`. Verdicts follow the import policy in `v0.7-external-sources.md`.

**Imports: none. Adaptations: none.** All eleven `llm/*` refs are our own text and cite their sources. Nothing was vendored, for four reasons:
- Provider documentation (OpenAI, Anthropic, Google, Mistral, Meta) is proprietary and changes faster than any pinned copy could keep up.
- The OpenTelemetry GenAI conventions are Apache-2.0, but they are still in *Development* status, so we link them instead of copying.
- The OWASP LLM Top 10 is CC BY-SA. Share-alike is not on our copy allow-list, and the OWASP sign-off pending since stage 2 stays pending.
- Several pages contain text addressed to AI agents: Expo, Maestro, Mastra, and the Pydantic AI docs, which ask agents to send telemetry about their "intent/stack/harness". We treated all of it as page data, followed none of it, and sent nothing anywhere. That alone is a reason not to vendor those pages.

Nothing new is waiting for `eos vendor review`.

## 2. Claims deliberately not made
- **No prices**, whether per-token, cache, batch, residency uplift as a currency amount, or WhatsApp per-message rates. The only number of this kind is OpenAI's 10% residency uplift, which is quoted as a percentage with its scope (eligible models released on or after 5 March 2026). `genai_otel.py` ships with an empty `PRICES` table that teams fill in from their own invoices or the vendor page.
- **No leaderboard rankings and no "best model" names.** Model names change monthly. The refs teach how to choose with your own evals and point to the official model pages.
- **No USSD short codes, gateway vendors or operator APIs.** We found nothing citable that we could verify, so USSD appears only as a deterministic fallback channel (no LLM inside a live session) with the advice to check the aggregator's limits on session length and message size.
- **No speaker numbers or percentages for Cameroon Pidgin or other local languages.** Ethnologue's figures sit behind a paywall and the page answers 403 to bot user agents; Glottolog has no speaker counts. IrokoBench supports the general gap; we did not extrapolate it to specific Cameroonian languages it does not cover.
- `openai.com/enterprise-privacy` returned 403 to both fetchers, so OpenAI retention claims cite the developer "your data" page only.
- The RRF paper PDF (uwaterloo) hung on every attempt, so the formula and default cite Elastic's reference instead of the paper.
- `temperature` is commented out in the prompt template ("only if your model accepts it"): we did not verify which current models accept it.
- No legal conclusions about Cameroon Law 2024/017 (cross-border transfer and consent sections are quoted, not interpreted). The text comes from OCR of the official PDF and must be checked against the original before anyone relies on it.
- The OTel GenAI conventions are *Development* status. The refs and scaffold say attribute names may change and pin the opt-in variable instead of claiming stability.

## 3. Enforcement decisions
- **`eos llm check`** (in-process, no tools). Prompt files are `*.prompt.md`, or `.md` files under `prompts/`, excluding READMEs. The rules:
  - LLM001: frontmatter missing or invalid.
  - LLM002: a required key is missing (`id`, `version`, `model`, `owner`, `evals`, `max_output_tokens` by default).
  - LLM003: the version is not a positive integer.
  - LLM004: the evals file is missing.
  - LLM005: `max_output_tokens` is invalid.
  - LLM006: a `{{var}}` is not declared in `inputs`. An unused input is a warning.
  - LLM007: an input marked untrusted is not wrapped in a delimiting tag.
  - LLM008: a secret-like value appears in a prompt.
  - LLM009: two prompt files share an id.
  - LLM010: the prompt changed but `version` was not bumped against `--base`.
  - LLM011: floating `-latest` model alias. This one is a warning only.

  Exceptions go in `.eos/config.json` → `llm.allow`, each with a written reason.
- **`eos llm gate`**: compares an eval results file with `evals/llm/gate.json`. It checks the minimum pass rate, per-tag minimums (for example, `safety` must be 1.0), the maximum drop against a committed baseline, the minimum case count, duplicate ids, non-boolean pass values, and cases that disappeared from the baseline. `--update` refuses to write a new baseline when the thresholds fail, so you cannot ratchet down by accident.
- **Lanes**:
  - trivial/spike: nothing runs;
  - standard: checks changed prompt files;
  - risky/one-way-door/`--full`: checks all prompt files and runs the gate when the results are newer than the change (otherwise it prints a note);
  - `eos check` runs `llm check` when prompt files exist.

  Prompt files are no longer classified as trivial Markdown. The fast path is unchanged.
- **`eos scaffold llm-evals`** generates:
  - a sample versioned prompt;
  - a 4-case JSONL dataset (FR/EN, a safety case, a prompt-injection case);
  - a stdlib runner with code graders, `--fake` for CI without keys, a `--max-calls` cost cap, and an explicit client timeout and retry count;
  - `gate.json`;
  - a CI workflow. Its prompt-lint job runs on every PR. Its eval job runs only on same-repo PRs, nightly or on manual dispatch, so fork PRs never get API keys. All actions are SHA-pinned, and model outputs are not uploaded unless `--keep-outputs` is set;
  - 8 Semgrep rules:
    - LLM output reaching eval/exec/shell/SQL (Python taint mode and JS);
    - provider keys behind public client env prefixes;
    - `dangerouslyAllowBrowser`;
    - missing output-token caps (Python and JS);
    - clients built without an explicit timeout (Python and JS).
- **`eos scaffold llm-otel`**: GenAI span and metric helpers for Python and TypeScript, following the current conventions, with message content capture opt-in and a cost estimate that only works once you fill in prices. Includes a pytest.
- **Not enforced, on purpose**:
  - Choosing a model or framework is a product decision.
  - Prompt-injection "detection" by pattern matching would give false confidence. Instead, LLM007 enforces delimiting tags, and the security ref covers capability separation.
  - Answer quality is measured by the team's eval dataset; no linter can judge it.
  - Hosted eval or observability vendors stay optional.

## 4. Human review needed
- The pending OWASP vendor sign-off from stage 2 is unchanged (the LLM Top 10 is linked, not copied).
- Security reviewers should read the Semgrep rules, LLM007/LLM008, `llm/tools-mcp` and `llm/privacy-residency` before teams rely on them. These are security guidance, and the taint rule has known gaps (the sources it recognises are listed in the rule).
- Someone has to own the eval gate thresholds and the first baseline. The scaffold's numbers are placeholders, and the 4-case dataset is a sample, not a test suite.
- The cost estimation in `genai_otel.py` and any spend limits are money code. A human sets the prices and limits.
- Quotes from Cameroon Law 2024/017 come from OCR. A lawyer should confirm them before any residency decision.
