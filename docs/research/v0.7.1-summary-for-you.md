# Does engineering-os speed you up? The short version (v0.7.1)

The full evaluation, with every number and how it was measured, is in [v0.7.1-efficiency-evaluation.md](v0.7.1-efficiency-evaluation.md).

**Mostly it speeds you up. Where it slows you down, it does so on purpose.**

- **Everyday work is quick.** On ordinary fixes and copy changes eos costs you about a second per task in total. Checking a change takes about 0.4–0.6 s and a commit about 0.4 s. The safety check on each agent action takes about 0.04 s. These were measured on the build machine.
- **v0.7.0 had become about twice as slow without anyone noticing.** The program had doubled in size and was being re-read from scratch on every call. That is fixed: v0.7.1 is faster than v0.6 on every path I measured.
- **The big library you added costs nothing until it is used.** Agents still start with the same ~1,900 tokens of rules as in v0.6. The 134 reference guides, the extra checks and the starter files appear only when a task needs them or when you switch them on.
- **One real annoyance is fixed.** Adding eos to a project, or updating it, used to produce a pull request saying "risky: please review 33 files line by line". Those files were all eos's own. Now it lists the 5 files that genuinely deserve a look.
- **Risky work is slower, deliberately.** Changes to payments, login or database migrations get a short plan, a full test run and your own careful review. New in v0.7: CI also checks that the new lines are tested. This is the part that protects you; I did not loosen it.
- **Learning costs more than running.** Expect about half a day to set it up and learn the basics. Over the first week, expect a few more hours to review the adoption PR and choose which extras to switch on. These are estimates.

**Two new tools for your AI agent.** Both are off by default; switch them on when needed:
- **Database (Postgres MCP).** The agent can look at your local database's structure, explain slow queries and check its health. It is strictly read-only and refuses anything that doesn't look like your own machine. Switch on with `eos mcp use debug`.
- **Browser (Playwright MCP).** The agent can open your local app, take screenshots at phone and desktop sizes, and run an accessibility check. It can only open localhost by default. Switch on with `eos mcp use debug-ui` or `design`.

**How to use it day to day:**
1. Start a task with `eos next` and finish it with `eos verify`. If the result says "trivial" or "standard", you're done.
2. If it says **"risky"**, read the short plan and review the listed files yourself.
3. Use `eos spike` for experiments and `eos hotfix` for emergencies, never `--no-verify`.
4. If you use Cline, keep the tool profile on "minimal" and switch to a bigger one only while you need it. In Cline, bigger profiles cost tokens on every message.
5. When you have a spare hour, review one of the 8 unsigned vendor packs. The design studio stays locked until you do. The agent is not allowed to approve them for you.
